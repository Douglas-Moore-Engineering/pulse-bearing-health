# ADR-009 — Explicit Bronze/Silver/Gold data layers

PULSE pre-Azure review v0.3 · 2026-10-10 · Owner: Dr. Douglas Moore · Prepared for review

Fictional customer scenario; proposed design, not implementation or customer approval. Stop boundary: no Azure connection, provisioning, paid resources, site access or production release.

Status: PROPOSED / pending Dr. Moore's review. Owner: Dr. Moore / DME architecture. This correction documents an architectural choice; it does not record acceptance.

Context: Pulse needs reproducible source evidence, source-specific signal/label validation, independent bearing/run evaluation and version-bound advisory products. The original lineage view described the stages but did not define explicit layer contracts, ownership or publication rules. That was an incomplete decision record for the pre-Azure review.

Proposed decision: organize the existing logical data path as Bronze (authorized originals/provenance), Silver (validated detailed observations and context) and Gold (versioned consumption products). Keep feature data, model predictions, human dispositions and observed outcomes distinct. Define quality/purpose/lineage gates in the [data architecture](../../docs/04-data-architecture-and-digital-thread.md) and [layer register](../../data/data_layers.csv).

Alternatives: retain generic raw/validated/curated names with equivalent controls; use a single undifferentiated dataset; or immediately build separate managed lakehouses for each layer. Equivalent generic layers can satisfy requirements. The single-stage approach obscures provenance/quality boundaries; separate managed services are premature without workload, operating and cost evidence.

Rationale: explicit layers make data quality and consumer eligibility reviewable using a familiar vocabulary while preserving the existing portable batch-first design. The name of the pattern is optional; the provenance, quality, leakage and authority controls are the substantive requirements. This does not imply automatic ACID transactions, proven data correctness or production readiness.

Consequences: retain raw fidelity within allowed retention; version transformations and manifests; quarantine failed records; prevent partial product publication and cross-partition leakage. Storage/reprocessing/retention costs enter the single lifecycle estimate. Logical paths alone cannot enforce access. No Databricks, Fabric or separate storage-account commitment is introduced.

Trace: PULSE-FR-001–002; PULSE-NFR-006–008; AIG-REQ-001. Verification: source-to-product lineage inspection followed later by executed quality, replay, leakage, access and retention tests; all runtime evidence remains pending.

Review triggers: actual source bytes/rights, volume/retention measurements, site adaptation, event-time/late-arrival behavior, transaction needs or cost comparison. Revisit physical layout and format when the platform plan has supported inputs. Azure remains unconnected and cloud entry remains blocked.
