# Private client review guide

Pulse is a fictional industrial reference engagement. Review the engineering approach and demonstration before discussing adaptation to your assets. No client deployment, endorsement or production detector acceptance is claimed.

## Fifteen-minute route

1. Read the [project status](../PROJECT_STATUS.md) and intended maintenance-review workflow (2 minutes).
2. Download or clone the private repository and open [benchmark-demo.html](benchmark-demo.html) locally (5 minutes). GitHub displays HTML source; this link is not a hosted app. Use the [presenter checklist](10-demo-readiness.md). This is recorded benchmark research, not live telemetry.
3. Inspect the [reference workflow diagram](../docs/diagrams/17_reference_detector_workflow.svg), [architecture decisions](../docs/12-architecture-decisions.md) and [180-test evidence](../governance/evidence/phase10-demo-tests.xml) (4 minutes).
4. Review [detector limitations](../data/qualification/DETECTOR_STATUS.md), [capacity findings](../docs/CAPACITY_STATUS.md) and the [proposed pilot](09-customer-pilot-package.md) (4 minutes).

## What this demonstrates

Authenticated assessment and durable evidence, simulated maintenance review, reproducible research, tested local recovery and explicit release boundaries. The offline demo is available without Azure access. Historical cloud evidence is dated evidence, not a current uptime promise.

## What needs a real engagement

Asset/sensor mapping, calibration, data rights, representative operating exposure and event labels, reviewer ownership, agreed acceptance thresholds and an authorized deployment/support scope. A pilot may establish integration before sufficient events exist to qualify detector performance. No operational maintenance action should rely on this reference.

Repository access is by invitation. Do not forward credentials, operator keys, private backups or customer data. No invitation or external message is sent by preparing this guide. Publication requires explicit owner authorization.
