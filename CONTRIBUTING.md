# Contributing and Evidence Discipline

Current reference-system change discipline. Consult PROJECT_STATUS.md and the active user authorization; original pre-Azure instructions are historical. No production or customer authority follows from a repository edit.

Preserve customer/requirement IDs and source history. Change scope, requirements, contracts, diagrams, thresholds or rights through recorded impact review. No secrets, customer operational data, proprietary records or raw datasets in Git. New numerical results need reproducible source/split/code/config and evidence digests. Run python scripts/validate_review_package.py before committing design updates. Validation of documents is not runtime V&V or independent assurance.

## Measurement and repository evidence

Maintain the seven-section README order and link quantitative results to the [measurement index](governance/measurements/README.md). Preserve exact units, denominators, original evidence versions and actual decision authority. New evaluations receive new record IDs; retrospective documentation is not a newly executed test. Keep customer outcomes **not measured** until observed and attributed.

Reusable DME skill packages are installed outside the project. Do not commit `SKILL.md` or copied instruction/reference bundles. Project-specific requirements, evidence, measurements and decision records remain in Git. Run `python scripts/check_repository_contract.py` before committing. Its structural checks cannot authenticate evidence or approve a release.
